Network / Outbound Proxy

Only needed if your host requires outbound HTTPS requests (to Telegram, WhatsApp, etc.) to go through a proxy. PythonAnywhere is the common case — its proxy is normally only available inside an interactive Bash console (via your shell profile), not inside your actual running web app, which is why a webhook can test fine from the console but still fail from the live site with a ProxyError/Tunnel connection failed. Setting it here makes every outbound bot request use it directly, regardless of how the web app was started. Leave blank if your host doesn't need one (most don't).

PythonAnywhere's documented proxy address is http://proxy.server:3128 — check their Internet Access help page for what's current on your plan.

Currency

Visitors can switch the currency prices are DISPLAYED in (bottom-left of every page) — rates auto-update every 6 hours from a free exchange-rate service. This only changes what's shown; actual checkout still charges through whichever payment gateway is configured (Paystack settles in ₦, Stripe in whatever you set it up for) — making the CHECKOUT itself charge dynamically per currency is a separate, bigger project tied to each gateway's own currency rules, not just a display setting.

Leave blank to always use the live auto-fetched rate. Set a value here only if you want to lock a specific rate regardless of what the market rate does (common for invoicing consistency).

        {{ url_for('admin.youtube_oauth_callback', _external=True) }}
      
    5. 
      
  5. Paste the Client ID and Client Secret below
    6.

If "Connect YouTube" shows an "Access blocked" / "app hasn't completed verification" screen from Google:

      
    
        
  1. This is Google refusing the login, not a bug on this site — youtube.upload is a "restricted scope" Google gates behind either Test User status or full app verification.
    2. 
        
  2. Fastest fix: in Google Cloud Console → your project → OAuth consent screen → Test users, add the exact Google account you're connecting with, then try again.
    3. 
        
  3. Permanent fix: submit the OAuth consent screen for verification (Google reviews restricted scopes separately and it can take days to weeks) — required before anyone besides added test users can connect.
    4. 
        
  4. Double-check the exact redirect URI below is pasted into Console character-for-character — a mismatch there shows as "Error 400: redirect_uri_mismatch" rather than "blocked", so if you're seeing that instead, it's this, not verification.
